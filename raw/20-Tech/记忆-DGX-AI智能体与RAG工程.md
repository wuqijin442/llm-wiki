# 记忆提炼：DGX AI 智能体与 RAG 工程（脱敏版）

> 来源：WorkBuddy 记忆档案 / Trae 记忆（已脱敏，隐去地址/账号/凭据）

## 总体形态

- 在 GPU 服务器上运行本地大模型（Ollama 系），通过统一 API 网关向业务侧暴露能力；网关由 agent 侧工具封装。
- 智能体按角色分权（admin / engineer / business），输出内容按 tier 分层：管理员看全面+修复建议；工程师看代码/任务工具+服务状态；业务侧看业务工具清单+简化状态+权限话术。
- 变更流程：提出变更申请 → 生成卡片（含文件差异/代码编辑指令/自动重载标记）→ 审批后由"执行器"应用 → 结果回写。

## 记忆铁律：LLM 内存上下文

- 针对特定平台调用必须显式配置 num_ctx（如 Dify 侧 8192）；harness 层可更高（16384）。
- 直接对话生成时：RAG 类用小步长输出（如 num_predict 1024）、超长超时；生成整文件代码时加大输出上限（如 4096~8192）。
- 大模型重写整文件有内容丢失风险；超过一定行数（如 >500 行）的文件应避免"LLM 全文重写"，改为由卡片直接携带完整新内容进行文件级替换。
- 自愈/重启类操作要避免"自杀"：正在执行器进程内运行的 agent 不应重启自身所在容器。

## RAG 组件

- 向量库（Qdrant/Milvus 一类）+ 嵌入模型（bge-m3 一类）构成检索底盘。
- API 网关与本地语言模型直连可以绕过业务网关（bypass）以减少耦合，但需清楚安全边界。

## 配置 Schema 的正确性陷阱（来自生产故障）

- 适配器配置 schema 若给 apiKeyEnv 声明了 default(DEEPSEEK_API_KEY)，即使未配置也会被客户端判为非空 → 触发不该有的"请输入 API Key"弹窗。
- 修复：将字段改为 optional() 且不带默认值；仅改 bundle/patch 配置而不改 schema default 是无效修复。
- 字段可选性由 required 决定，可通过 meta.required 查看；这属于 schemastery 一类 schema 库的通用机制。

## 多数据源与诊断

- 诊断能力分档并行探测：数据库连通性、向量库集合数、本地模型数、容器状态、公网站点可用性，任一失败不影响整体，仅给修复建议。
- 变更执行器读原文件 → LLM 生成新内容 → 写入 → 可选重启 → 回写执行结果，形成闭环。
