# 记忆提炼：EMS 储能系统研发优化（脱敏版）

> 来源：WorkBuddy 记忆档案 / Trae 记忆（项目用于学习示例，已脱敏，隐去地址/账号/客户名）

## 架构概览

- 三端形态：后端服务（Spring Boot + MyBatis-Plus + Maven / JDK 17 + MySQL）、管理后台前端（Vue 2.6 + vue-cli 4.4.4 + webpack 4 + acorn 6 + Element UI + Options API + ECharts）、大屏展示端（同样 Vue 技术栈）。
- 约束：旧前端栈不支持 ES2020 的可选链 `??` 与 `?.`，新增代码必须规避。
- 三语 i18n（简中/繁中/英文），命名空间需扁平化，专业指标名（如 SoC）保持不翻译。

## 多租户与数据路由

- 采用主库 + 多子租户库的架构，通过动态数据源（连接池 + 租户上下文）按请求路由。
- 登录返回设备类型但不入参，后续请求按过滤器基于设备类型路由；租户表通过设备/公司归属识别。
- 跨租户的建表/结构变更走主数据源，业务读写走对应租户数据源。

## 业务模型（设备/主机）

- 设备类型枚举：并网（单机）/ 汇流（主机）。并关联 parallel 标志区分：单机 / 主机 / 从机。
- 约束规则：主机必须绑定至少 1 个子设备；单台单机仅可被 1 台主机绑定。
- 派生概念：主机与从机形成"汇流柜"聚合，前端渲染需区分单机视图与汇流柜聚合视图。

## 精度与单位规范（关键教训）

- 计价显示采用 NT$/kWh，后端用 CNY 存储并用小数 DECIMAL(10,4)，涉及汇率双向换算 → 产生精度丢失，客户感知为显示误差（如 9.41 vs 9.39）。
- 教训：显示单位与存储单位不一致时，换算会引起精度问题；解决方向是"显示层仅做标识，不参与存储与换算"，存储侧用足够精度的 decimal 对齐。
- 全系统单位（kW/kWh/V/A/%/NT$/kWh）必须严格统一大小写。

## 常见问题模式

- 工厂日/月用电量取到相同值 → 后端 SQL 聚合条件缺失（时间维度未下钻）导致的 BUG。
- 前端"看不出变化" → 多为缓存未刷新 / 改错位置，排查应结合 DevTools Console + Network。
- 文件级 diff 爆炸 → 编辑工具把整文件 CRLF→LF 转码，需校验 CR 计数防止 git diff 污染。

## 方法论沉淀

- 精度类 Bug 采用"截图 + diff + 场景模拟"三重验证定位根因，改动以"根因/变更/场景模拟/验证"四列表格呈现。
- 前端只改代码不碰后端、不经用户批准不构建不提交，提交动作由用户在确认后统一执行。
- 语言/单位/命名统一性校验（模板编译、残留 grep）在每次改动后执行。
