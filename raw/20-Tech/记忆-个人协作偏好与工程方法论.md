# 记忆提炼：个人协作偏好与 AI 工程方法论（脱敏版）

> 来源：WorkBuddy 记忆 / Trae 记忆（已脱敏，保留通用、可复用原则）

## 沟通偏好

- 中文沟通，简繁皆可。偏好简洁循证、结构化粗体、表格化对比、编号问题汇总、结论先行、根因分析。
- 对"无验证的结论"会主动反驳并要求截图 / refs / git diffs 交叉验证；AI 应先看图再分析。
- 需求常单条消息多层次并附带截图，期望快速迭代；视觉无变化时立刻反馈（便于排查缓存/未刷新/改错位置）。
- 用单个词指令（"改""排""删掉"）驱动工作流；确认环节偏好简短指令式（"两点都做""接着干"）按编号推进。

## 工作纪律（AI 侧强约束）

- 只改前端不碰后端；不经用户批准不得自动构建 / 提交；扩散最小化，只改目标样式。
- 新增代码零 `??` / `?.` 等新语法、零硬编码英文文案、最小 diff、未构建未提交。
- 用户反复改变 UI 决策时，AI 跟随 revert，不满意直接恢复原代码要求重做。
- 倾向彻底删除不留备份（须用户确认后）。
- 给路径先校验再执行；操作后主动校验（模板编译、残留 grep、CR 计数）再回报完成。

## 工程方法论

- 精度类 Bug：重视客户满意度，对数值精度极为敏感；采用"截图 + diff + 场景模拟"三重验证定位根因，改动以"根因/变更/场景模拟/验证"四列表格呈现。
- 涉及后端冲突结论：以实测证据优先（抓包 / 计数器 / git diff），明确证据与结论的不符，并给出双方可复验的判定口径。
- 跨平台协调问题（Android/Windows 是否同样适用）要一并覆盖，而非只答单平台。
- 读源码 + git 交叉验证再改；技术修复后用 bullets 总结，不自动 build/commit。

## 跨会话记忆维护

- 维护会话级项目记忆日志（如按日期的 md、项目专属 MEMORY.md、work-log markdown），跨 session 跟进多任务。
- 任务交接/汇报采用结构化模板，让非技术读者也能看懂（如"背景/目标/已完成内容/涉及模块"四段式）。
- 复杂任务的中断续跑：长时任务中断后说"继续"，要求同一回合阻塞等待，避免后台进程被回收。

## 审美与产品倾向

- 多套视觉语言可复用（冷工程极简 / Y2K 霓虹 / 极简主义），视目标受众选择；标题/正文有字数约束。
- 重学习：每个重要功能实现后要求记录、深度分析、解释原理，通过项目实践理解技术底层。
