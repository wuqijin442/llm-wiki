# 记忆提炼：跨平台 VPN 客户端研发与合规（脱敏版）

> 来源：WorkBuddy / Trae 记忆（已脱敏，隐去 Bundle ID、服务器、账号、团队标识、客户名）

## 项目形态

- 基于 Web 组件技术栈（Lit）作为 UI 层，通过 Cordova 打包 Android、Electron 打包桌面、Xcode 打包 iOS；原生传输层用 Swift 重写（自定义 TLS 帧协议）。
- 多平台（iOS/Android/Windows）通过统一的下发机制（transportConfigLocation）共享同一份传输配置，保证行为一致。
- 内网仓库存在多套 git 服务（公网、内网、Code 托管），push 到不同远端需按目标切换远程地址，注意 keep 分支语义一致。

## 关键技术点

- 系统网络栈：IPv4/IPv6 隧道语义、tun 设备地址通告与路由通告（`::/0` IPv6 默认路由通告可能导致 IPv6 流量黑洞）。故障定位思路：统计计数（上行/下行字节）非零 → 证明流量进入隧道，可据此反驳"隧道死掉"的结论。
- 不同 git 平台对 CI 的支持差异：仅公网托管执行 GitHub Actions；push 到内网托管不会触发。
- CI 工作流触发条件：push 到 main/master 且命中特定路径（client/、infrastructure/、package.json 等）才触发；"Canceled after 0s" 表示被取消/被抢占而未执行，并非构建失败。

## App Store 合规要点

- 内部分发（Unlisted）与下载权限、隐私政策链接、加密出口（ERN）、崩溃符号化（dSYM）。
- 常见拒审：重复内容（ITMS-91054）、隐私条款（5.1.x）、及"代码/功能/定位重复"类（4.3.a）。
- 团队/签名标识一致性（Team ID 位数、公司名与签名主体一致）是打包分发前必须核对的项。
- 指纹规避：第三方实现带有指纹特征（多处可识别特征），评估自研替代以降低分发风险。

## 方法论

- 汇报采用双版本：老板可见摘要（严重度+可执行建议+无法解决项）+ 内部完整清单；每条合规/违规论断须引用官方文档出处，证据坐实。
- 涉及后端结论冲突时：以实测证据（抓包/字节计数）优先，明确指出证据与结论不符之处，并给出双方可复验的抓包口径。
