# 用 WorkBuddy / Codex + Obsidian 搭建自生长的个人知识库实战

> 原始素材存档（来源见 frontmatter）。基于 Karpathy 公开的 **LLM wiki** 知识库构建方法与架构做的落地实践。
> 存档说明：本文为原文核心结构的整理存档，用于知识库 ingest；完整原文请访问上方链接。

## 一、问题的起点

主流玩法（RAG 系统、NotebookLM、GPT 文件上传）本质是同一套流程：先上传资料，提问时召回相关片段，再临时综合出答案。

问题在于：**每次提问，模型都在从碎片里重新拼答案，答完就散。** 同样的问题问一百遍，它就重新拼一百遍，知识本身没有任何积累。

## 二、什么是 LLM wiki

可以理解成给 AI 安排一份长期工作：**持续维护知识库**。

每加入一份资料，Agent 都会先查看现有页面：

- 已有内容 → 补充
- 新概念 → 单独建页
- 不同观点 → 把**来源、时间、适用范围**一起留下

知识的分歧因此有迹可循，也不会被一段看似完整的总结悄悄抹掉。

**"自生长"的关键**：AI 处理完资料后，知识库必须留下变化——可能新增一个概念、补上一条关联，也可能暴露一个暂时没有答案的问题。一次次变化累积，才形成真正属于自己的知识体系。

## 三、三层架构

| 层 | 职责 |
| --- | --- |
| **Raw 层** | 保存文章、论文、聊天记录等原始资料 |
| **Wiki 层** | 沉淀 AI 整理出的概念、实体和主题 |
| **Schema 层** | 规定 AI 如何归档、更新、引用，以及怎么处理冲突 |

一句话：**Raw 保存证据，Wiki 记录理解，Schema 负责定规则。**

## 四、为什么是 Obsidian

1. **完全本地化和数据自主**：一个 Vault 就是普通文件夹，笔记以 Markdown 纯文本保存，不依赖平台页面数据库。工具可以换，知识不用跟着搬家。
2. **文件形态适合 Agent 工作**：Agent 可直接读取目录、创建页面、修改链接、维护索引；每次变化都能定位到具体文件，还能用 Git 留记录。
3. **双链 / 反向链接 / 知识图谱**：把概念、人物、工具、主题连接起来，帮助发现核心节点、孤立页面和新的关联。
4. **插件生态**：模板、查询、版本管理、发布、可视化按需添加。

Obsidian 承担 **存储底座 + 人机操作界面 + 知识观察窗口**；WorkBuddy / Codex 负责执行。对于需要长期使用的个人知识库，本地自主、结构开放、变更可追踪、能力可扩展，已足够构成选择理由。

## 五、Agent 在这一层做什么

- **入库**：理解内容 → 识别概念/实体/主题 → 与现有 Wiki 对照 → 补充已有内容、创建新页面、建立链接；遇不同说法保留来源、时间、适用范围；同步更新索引与变更记录。
- **查询**：检索相关页面、整理答案、追溯来源。
- **维护**：批量检查失效链接、缺失字段和长期没有更新的内容。
- 全程**增量维护，不需要反复重建整套知识库**。

分工：**人负责设定规则、检查结果和处理关键判断；Agent 承担重复维护。**

## 六、三种搭建方法（按上手难度递增）

### 方法一：直接搭建法
在 Agent 中打开 Vault，说：

```text
你现在是这套个人知识库的搭建与维护 Agent。请在当前 Obsidian Vault 根目录中，搭建一套可长期增量维护的 LLM Wiki。
```

Agent 按三层架构建目录并定义 `AGENTS.md`。之后：

```text
请读取 `raw/articles/` 中新增的文章，并严格按照 `AGENTS.md` 的规则增量维护 Wiki。
```

- 优点：完全可控，Schema 可深度自定义
- 缺点：对提示词与工程化理解要求高，`AGENTS.md` 需不断调整

### 方法二：Skill / 插件封装法（claude-obsidian）
把初始化、入库、索引、检索封装成可复用的 Agent Skill：

- `ingest` — 同步新素材到 wiki
- `retrieve` — 从知识库查询（甚至不用显式指定，Agent 会自动命中 wiki）

- 优点：省去反复写提示词与维护复杂规则
- 缺点：操作仍发生在 Agent 侧，任务状态与知识变化缺少可视化反馈

### 方法三：Obsidian 插件法（如 WeSight 知识大脑）
把知识库初始化、资料入库、Wiki 更新、智能检索整合进 Obsidian 内部，后台 Agent 负责结构维护：

- 一键开启「知识大脑」，自动配置环境与结构
- 一键把当前笔记加入知识大脑对应 wiki
- Chat 时选「基于知识库」模式，自动完成检索、引用与上下文装配
- 可把与 Agent 的聊天记录一键存入知识大脑

- 优点：可视化、门槛最低
- 缺点：依赖插件能力与授权（当时为少量内测）

## 七、素材收集入口

| 场景 | 工具 |
| --- | --- |
| 电脑看文章 | Obsidian Web Clipper 浏览器插件，一键剪藏到 `raw/articles/` |
| 手机上 | ima / 其他剪藏工具，乃至 WorkBuddy 小程序 |
| 飞书文档等散落资料 | 借助 Agent 收藏进知识库 |

## 八、核心观点摘录

- "自生长"来自**知识结构的持续增量更新**：每次处理都留下可复用的结构化结果，知识库随输入演化。
- **人 + Agent 各司其职**：人处理判断与规则，Agent 处理重复、耗时且结构化的维护工作，知识管理才有机会长期坚持。
- **不要一开始就搭出完美系统**：先建好三层目录，放入一篇真实资料，让 Agent 完成第一次增量更新，再根据实际使用不断调整 Schema。

> 模型选型建议（原文）：优先长上下文模型；追求性价比可选 DeepSeek V4 Flash（不支持多模态）；长链路多轮任务需关注上下文容量、工具调用稳定性、指令遵循与结构化输出能力，建议用真实资料跑一遍完整任务再决定。
