# 双环知识飞轮

## 定义

在「AI 自增长知识库」之上补一个环的模型：**编译环**让库变聪明，**互动环**让人变聪明，两者由一条**回流带**咬合成飞轮。

作者的核心论断：市面上九成的「自增长知识库」只转了半圈——它们是**快照**（一次性搬运）而非**飞轮**（不靠手动喂、自己越转越快）；即便真做到了自增长，那也只是「AI 的飞轮」，因为**写库的是 AI，人的大脑一个神经元都没变**。

## 第一个环 · 编译环（让「库」变聪明）

用 AI 把外部资料「**编译**」进库，而不是「存储」：

| 模式 | 动作 | 结果 |
| --- | --- | --- |
| 存储 / RAG | 原样塞回去、按相似度捞出来 | 东西仍是一个个**孤岛**，只是变得能搜 |
| 编译 | AI 读进去、消化掉、用自己的结构重写一遍 | 重写时主动找邻居、标矛盾 → 形成**网络** |

一句话：**存下来的是孤岛，编译过的是网络。** 对应 [[ICAP学习框架]] 的 C（建构）——但强调「只是 AI 的建构，不是我的」。

## 第二个环 · 互动环（让「我」变聪明）

不是「我问、AI 答、我点头」（那还是 P），而是逼人做三件反本能的事：

1. 用自己的话把一个模型**重新讲透**；
2. 拿真实战场上的问题去**压测**它；
3. 让 AI 当场**挑漏洞并反驳**自己。

对应 ICAP 的最高层 I（互动）。关键洞察见 [[ICAP学习框架]]：费曼学习法本质上只到 C，听众必须是能挑刺的圈内人才能升到 I——而 AI 第一次让这个「圈内人」角色随叫随到。

## 回流带（把两个环咬合成飞轮）

单一环的死穴是：互动环聊出的好东西，一关聊天框就蒸发。回流带做两件事，互为因果：

1. **洞察回流**：互动中产生的洞察、对旧模型的修正，定时自动流回编译环；
2. **库反哺提问**：编译好的库让下一轮提问更准、更锋利。

作者实现方式（`harvest.py` 三动作）：

| 动作 | 内容 |
| --- | --- |
| 抓 | 读本地对话记录 `transcript.jsonl`，**记住上次行号断点**，只读新增部分，不重复劳动 |
| 炼 | 调「无头」AI（headless）筛出洞察 / 框架 / 修正，**滤掉约 90% 过程性闲聊**（垃圾进垃圾出） |
| 写 | 把提炼结果写回 `raw/`，编译进库、连进图谱、追加日志 |

调度上强调：**定时必须挂在系统级**（作者用 Windows 计划任务，每天 13:00 / 23:00 各一次）。放在对话进程里的定时不可靠——进程一结束就被回收。

> **复利的本质不是「多」，是「连」**：339 个模型不是 339 个孤立条目，而是彼此握手、还和每天对话握手的节点。

## 搭建顺序（三步，别贪全）

1. **先编译一本书** → 让编译环转起来（Obsidian 作容器 + LLM Wiki 作方法论 + WorkBuddy 作引擎）。此步只证明「库在长」，未证明「你在长」。
2. **再开互动通道** → 把真实问题灌进来，并把「我问→AI答→我点头」改造成重述 + 被质疑 + 修正。
3. **最后接回流带** → 这一步才让两个环成为一台飞轮。

## 三个自测题

1. 存进去的东西会主动连到别的知识吗？（编译过才会，否则是 A 级搬运）
2. 聊出的洞察有固定出口流回库吗？（没有就随风散了）
3. **最狠的一问：转了一圈之后，变聪明的是「库」，还是「你」？**

## 待核实

- 本文对「市面上九成自增长库只转半圈」的判断属作者主观抽样，**无数据支撑**，不宜当作统计结论引用。
- `harvest.py` 的「炼」环节依赖判断「哪些洞察值钱」，原文未给出筛选标准或准确率，**模型误判导致污染库的风险未评估**。
- 三个自测题是启发性自评，**无评分标尺**，不同人给出不同答案时无法比较。
- 作者提到 5 本书 / 339 模型 / 550+ 节点，为个人实践数据，**不可复现验证**。

## 对照：harness 自进化（另一种「自生长」）

[[Proteus]] 代表的 [[Harness自进化]] 与本模型关心的不是同一层：

| | 双环知识飞轮 | Harness 自进化（Proteus） |
| --- | --- | --- |
| 演化对象 | 知识库编译产物 + 人的理解 | agent 自己的运行脚手架（harness） |
| 主体 | 人 + 维护库的 AI | harness 自身（外框架做事务） |
| 「长了吗」的判据 | 有无结构化 diff、复利是否「连」 | 结构距离 / 行为距离 / 结晶（见 [[自进化测量标尺]]） |
| 共同点 | 都拒绝「只存不编译」；都要求留下可复用的结构化变化 | |

本库（llmWiki）处在左列；Proteus 的测量纪律（churn 分辨堆积/策展、travel 用路径长度、先 reliability 再比较）可反哺左列的 [[growth]] 指标设计。
