# 混合跨平台客户端架构

## 定义

用一套 Web 组件技术栈（Lit）承载 UI，再按目标端选择对应壳层打包的架构：

| 端 | 打包方式 |
| --- | --- |
| iOS | Xcode |
| Android | Cordova |
| 桌面（Windows 等） | Electron |

对性能敏感的传输层不走 Web，用原生（Swift）重写自定义 TLS 帧协议——即"Web 管界面、原生管管道"的分层。

## 关键机制

- **传输配置统一下发**：多平台通过 `transportConfigLocation` 共享同一份传输配置，保证 iOS/Android/Windows 行为一致，避免各端配置漂移。
- **多 git 远端并存**：公网、内网、Code 托管多套 git 服务，push 到不同远端需按目标切换远程地址，并注意 keep 分支语义一致。
- **CI 差异**：仅公网托管触发 GitHub Actions，push 到内网托管不会触发；工作流命中 main/master push 且特定路径（client/、infrastructure/、package.json 等）才执行。

## 排障经验

- IPv4/IPv6 隧道语义不同，`::/0` IPv6 默认路由通告可能导致 IPv6 流量黑洞。
- 隧道"是否活着"用统计计数判断：上/下行字节非零即流量在隧道内，可据此反驳"隧道死掉"的结论——把结论交给可复验的证据，见 [[个人AI工程方法论]]。
