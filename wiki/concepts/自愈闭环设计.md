# 自愈闭环设计

## 概述

让 LLM 具备安全改码/重启能力，同时**避免跨容器权限爆炸与进程自杀**。核心：由宿主上的极简执行代理承载写盘与重启，业务容器不挂 docker.sock、不重建、不自重启。

## 安全通道三要点

### ① 执行通道放宿主
- 业务容器无 docker.sock/CLI，且不挂 sock、不重建（保生产零中断）。
- 宿主跑极简执行 agent，监听本地环回端口；业务容器为 host 网络可直连。
- 内部 token 经 `docker cp` 注入容器内文件（root 600），**不进 env/命令行**。

### ② 白名单双端校验
- 文件仅限指定前缀路径（如 addons 目录子路径，禁 `..` 穿越）。
- 可重启容器白名单，且**工具只暴露其中一个**（自身容器不暴露，避免自重启=进程自杀）。
- 删除类操作**不暴露为 LLM 工具**，仅运维直调；配合 `backup:false` 开关防止删 .bak 时套娃出新的 .bak。

### ③ 批准执行器语义
- 批准后**只执行 `code_edit`**：`{path, instruction, auto_reload}` → LLM 读原文件改写（或新建）→ 写入 → 按需重启 → 结构化回写执行结果。
- `file_diffs` 仅展示 `{file, diff}` 草案，**无 patch 应用能力，绝不自动执行**。
- 写前自动 `.bak_<ts>` 备份；重启异步调度、不阻塞批准响应。

## 验收基线
- 回归脚本覆盖：档位过滤/拦截、路径与容器白名单负测、能力探针、approve→改码→落盘→读回、容器真实重启。
- 回归脚本**内置自清**（冒烟不污染审批列表/数据库）。
- 终态回写：`reload_status` 从 running→done/failed + `reload_finished_at`，供前端轮询。
