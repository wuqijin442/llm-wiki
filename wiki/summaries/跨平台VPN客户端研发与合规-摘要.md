# 跨平台VPN客户端研发与合规摘要

> 来源素材：[[raw/20-Tech/记忆-跨平台VPN客户端研发与合规]]（WorkBuddy / Trae 记忆，已脱敏）

## 核心要点

1. **一套 Web 组件栈打多端**：UI 层用 Lit，打包分别走 Cordova（Android）、Electron（桌面）、Xcode（iOS）；传输层原生部分用 Swift 重写（自定义 TLS 帧协议）。
2. **传输配置统一下发**：多平台通过 `transportConfigLocation` 共享同一份传输配置，保证各端行为一致。
3. **隧道故障定位有"证据法"**：统计计数（上/下行字节）非零即可证明流量进入了隧道，可据此反驳"隧道死掉"的结论；注意 `::/0` IPv6 默认路由通告可能导致 IPv6 流量黑洞。
4. **CI 触发语义**：仅公网托管触发 GitHub Actions，内网托管 push 不触发；"Canceled after 0s" 表示被取消/抢占，并非构建失败。
5. **App Store 合规四件套**：Unlisted 内部分发与下载权限、隐私政策链接、加密出口（ERN）、崩溃符号化（dSYM）。
6. **汇报双版本**：老板可见摘要（严重度 + 可执行建议 + 无法解决项）+ 内部完整清单；每条合规/违规论断引用官方文档出处。

## 详细摘要

- 多套 git 服务并存（公网、内网、Code 托管），push 到不同远端需切换远程地址，注意 keep 分支语义一致。
- CI 工作流触发条件：push 到 main/master 且命中特定路径（client/、infrastructure/、package.json 等）才触发。
- 常见拒审类型：重复内容（ITMS-91054，素材原文如此）、隐私条款（5.1.x）、"代码/功能/定位重复"类（4.3.a）。
- 团队/签名标识一致性（Team ID 位数、公司名与签名主体一致）是打包分发前必须核对项。
- 指纹规避：第三方实现存在多处可识别的指纹特征，评估自研替代以降低分发风险。

## 个人理解与启发

- "字节计数非零即流量在隧道内"是把玄学问题转成可复验证据的典型手法，与 [[个人AI工程方法论]] 的"证据优先"原则同源。
- 合规论断必须挂官方文档出处，否则汇报口径站不住。

## 待核实
