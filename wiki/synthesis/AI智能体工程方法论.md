# AI智能体工程方法论

从长期工程记忆提炼，聚焦**可复用的工程原则**（不涉凭据细节），适用于自托管 LLM 智能体系统。

## 1. 部署一致性铁律
- **镜像烤代码、无 bind mount**：代码经 `scp → docker cp → restart → 容器内 grep/md5 校验`，不信任陈旧宿主快照。
- **compose 重建 = docker cp 归零**：容器内代码会随重建清空，依赖（若未固化进镜像）需重装。→ 改 compose **只改文件不重建容器**，`config -q` 验证待下次重建生效。
- **反向漂移同样致命**：服务器侧改码必须回填本地；验收 = local ↔ 容器 md5 逐一字节一致。
- **ssh 复合命令必炸**：复杂远程操作写本地脚本 scp 上去执行；命令行明文传 key 会触发敏感审批卡死 → 脚本内从容器 env 实时读 KEY。

## 2. 自愈闭环（无 docker.sock 的安全通道）
- 改码/重启类自愈不在容器内做（规避 sock 挂载与自重启自杀），而是宿主起极简执行 agent，通过**白名单双端校验**（文件路径 + 可重启容器）+ **base64 注入 + `.bak` 备份** + `/delete` 不暴露为 LLM 工具（仅供运维直调）。
- 批准执行器只执行 `code_edit`（LLM 读原文件改写/新建→写入→按需重启），`file_diffs` 仅展示草案、**绝不自动执行**。详见 [[自愈闭环设计]]。

## 3. token 预算与截断纪律
- **numCtx 过低会静默截断工具清单 → 模型幻觉**（凭空造工具名）。设硬限并核算每新增工具/上下文段的 token 预算。
- **`TOOL_RESULT_MAX` 通用截断会毁结构化结果**（截成 JSON 残片字段全丢）→ 新增"读大内容"工具必须自带**分页**（from/to/total + offset 续读），永不超过上限。
- **工具结果不得以 role:'tool' 结尾**（会 500）→ 以 user 消息回传。
- 视觉/思考模型的输出预算会被 `message.thinking` 吃掉 → 需显式设 num_predict 增大 + 空输出重试。

## 4. 意图路由 + 服务端确定性兜底
- 路由正则 + 粘性命中（会话键/账号键双键），且**任何新意图都要考虑两个端点族**（RAG 端点走 tryTaskIntent，命中不了正则就掉纯 RAG 无工具）。
- **LLM 自觉不可靠 → 服务端兜底**：命中改码意图但无登记卡片 → 服务端强制补登记一张审批卡片，零副作用（批准前不执行）。详见 [[意图路由与服务端兜底]]。

## 5. 跨工程师协作契约
- **回执唯一权威版**：只维护一份总回执，旧文档归档并更新索引；合并多份文档时统一重排节号防冲突。
- **不空口承诺契约**：收到对方期望的 schema，先实装上线再回执，回答附实测数据。
- **部署指纹现场重算**：md5/字节数必须现场实测，严禁沿用上轮表格（代码持续在变）。
- **验收以容器真身 md5 为准**，不只看对方回执声明；反向漂移在回执前就消灭。
