# 个人AI工程方法论

## 核心原则

### 证据优先
不以未经验证的结论为准。修复/反驳时用**截图 + diff + 场景模拟**三重验证，涉及后端冲突结论时以实测证据（抓包 / 计数器 / git diff）说话。

### 最小干预
只改目标文件与目标样式；新增代码遵守新语法规避、零硬编码文案、**最小 diff**；未经批准不自动构建、不提交。

### 反馈闭环
视觉无变化 → 立即反馈（缓存/未刷新/改错位置）；改错 → 恢复原代码重做；不满意直接 revert。AI 跟随用户决策迭代。

### 跨会话记忆
维护会话级项目日志（日期 md / 项目 MEMORY.md / work-log），跨 session 跟进多任务；交接用结构化模板让非技术读者可懂。

## 可复用的工程模式

- 精度类 Bug：根因 / 变更 / 场景模拟 / 验证 四列表格呈现。
- 分权：按 admin / engineer / business 分层，变更经申请-审批-执行-回写闭环（见 [[AI智能体分权治理]]）。
- 单位/语言/命名：显示与存储分离（见 [[显示与存储单位分离]]），语言命名单一且严查大小写。
- 本地优先：自持工具链 + 硬件预算内调度 + 灰度降级（见 [[本地优先AI创作]]）。

## 落地建议

给 AI 侧使用的 checklist：改前读源码 + git 交叉验证 → 校验路径 → 最小 diff → 改后模板编译/残留 grep/CR 计数校验 → bullets 总结，不自动提交。
